# FF001 — Activity Orientation is Restricted

## Overview
- **Rule ID**: `FF001`
- **Category**: Manifest Rule
- **Default Severity**: `WARNING`
- **Default Confidence**: `MEDIUM`

## What It Detects
`FF001` detects `<activity>` tags in `AndroidManifest.xml` that explicitly set `android:screenOrientation` to a fixed or restricted orientation mode (such as `portrait`, `landscape`, `reversePortrait`, `reverseLandscape`, `sensorPortrait`, `sensorLandscape`, or `locked`).

## Why It Matters
Hardcoding activity orientation prevents the app from adapting when users:
1. Rotate foldables, tablets, or Chromebooks.
2. Unfold a foldable device into landscape mode.
3. Open the app in Android split-screen or freeform windowing mode.

*Platform Note*: On Android 16 (API 36+), orientation restrictions are ignored by default on displays with smallest width $\ge 600\text{dp}$ unless explicitly opted out, but restrictions remain active on compact screens and older platform versions.

## Bad Example
```xml
<activity
    android:name=".MainActivity"
    android:screenOrientation="portrait" />
```

## Better Alternative
```xml
<activity
    android:name=".MainActivity"
    android:configChanges="orientation|screenSize|smallestScreenSize|screenLayout" />
```

## Known Limitations & False Positives
- **Camera / Games**: Certain camera preview or specialized sensor-locked activities legitimately require fixed orientation. Use ViewLint baseline or inline suppression where appropriate.
