# FF004 — Fixed Large Inner Dimensions

## Overview
- **Rule ID**: `FF004`
- **Category**: XML Layout Rule
- **Default Severity**: `INFO`
- **Default Confidence**: `LOW`

## What It Detects
`FF004` traverses XML layout hierarchies to identify non-scroll container inner child elements that lock both `android:layout_width` and `android:layout_height` to hardcoded dimensions $\ge 300\text{dp}$.

## Why It Matters
Views with hardcoded large bounds on both axes cannot flex when container constraints change, leading to layout truncation on smaller screens or awkward empty spaces on larger displays.

## Bad Example
```xml
<ImageView
    android:layout_width="350dp"
    android:layout_height="400dp"
    android:src="@drawable/hero" />
```

## Better Alternative
```xml
<ImageView
    android:layout_width="match_parent"
    android:layout_height="0dp"
    android:layout_weight="1"
    android:scaleType="centerCrop"
    android:src="@drawable/hero" />
```

## Known Limitations & False Positives
- Dedicated map view containers or fixed aspect-ratio custom cards may legitimately use large fixed dimensions.
