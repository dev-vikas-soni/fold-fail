# FF009 — Missing Adaptive Layout Handling

## Overview
- **Rule ID**: `FF009`
- **Category**: Compose Rule
- **Default Severity**: `INFO`
- **Default Confidence**: `LOW`

## What It Detects
`FF009` identifies screen-level composables (e.g. function names containing `Screen`, `Dashboard`, `Page`, or containing `Scaffold` / `NavHost`) that contain substantial layout logic but lack detectable adaptive cues (`WindowSizeClass`, `calculateWindowSizeClass()`, `BoxWithConstraints`, or adaptive scaffold components).

## Why It Matters
Top-level screens without adaptive handling render as stretched phone layouts when launched on foldables, tablets, or multi-window desktop configurations.

## Bad Example
```xml
@Composable
fun DashboardScreen() {
    Column(modifier = Modifier.fillMaxSize()) {
        // Multi-region screen layout without WindowSizeClass checks
    }
}
```

## Better Alternative
```xml
@Composable
fun DashboardScreen(windowSizeClass: WindowSizeClass) {
    if (windowSizeClass.widthSizeClass == WindowWidthSizeClass.Expanded) {
        TwoPaneDashboardLayout()
    } else {
        SinglePaneDashboardLayout()
    }
}
```

## Known Limitations
- If adaptive branching occurs in a parent container outside the analyzed file, `FF009` may produce a low-confidence informational finding.
